# نصیر VPN (Nasr VPN) — افزونهٔ Chrome مدیریت سابسکریپشن پروکسی

افزونهٔ Manifest V3 برای دریافت سابسکریپشن‌های پروکسی، نمایش سرورها و تأخیر آن‌ها، و اعمال پروکسی سازگار در Chrome — شامل اتصال به هستهٔ محلی (Xray/sing-box) برای پروتکل‌های VLESS/VMess/Trojan/Shadowsocks.

## امکانات
- دریافت سابسکریپشن از لینک با فرمت‌های: Base64/URI، Clash Meta (ساده)، sing-box/V2Ray JSON
- **پشتیبانی از Mirror**: اگر سرور اصلی شکست خورد، لینک mirror (مثلاً `raw.githubusercontent.com`) امتحان می‌شود
- **ورود دستی سابسکریپشن**: چسباندن مستقیم محتوای Base64/URI/Clash/JSON در تنظیمات (با گارد URL تکی و HTML)
- نمایش سرورها با پروتکل، نام، میزبان/پورت
- اندازه‌گیری «زمان پاسخ HTTP» به‌عنوان معیار تأخیر (نه پینگ ICMP)
- اعمال پروکسی با `chrome.proxy` فقط برای HTTP/HTTPS/SOCKS4/SOCKS5
- **اتصال به هستهٔ محلی (Local Core Bridge)**: ست کردن پروکسی Chrome روی inbound محلی هسته (HTTP/SOCKS) برای اجرای پروتکل‌های پیشرفته
- به‌روزرسانی خودکار زمان‌بندی‌شده (chrome.alarms)
- ذخیرهٔ تنظیمات در `chrome.storage.local`، پاک‌سازی کامل داده‌ها
- رابط فارسی راست‌چین

## چرا سرورهای VLESS/VMess/Trojan/Shadowsocks با chrome.proxy کار نمی‌کنند
`chrome.proxy` فقط پروکسی‌های HTTP/HTTPS/SOCKS را می‌فهمد. VLESS/VMess/Trojan/Shadowsocks پروتکل‌های رمزنگاری‌شدهٔ مستقل هستند که به یک **کلاینت/هسته** (Xray، sing-box، v2ray، …) نیاز دارند تا آن‌ها را به یک inbound سادهٔ HTTP/SOCKS روی سیستم تبدیل کند. افزونه در سندباکس MV3 اجرا می‌شود و نه اجازهٔ اجرای باینری خارجی دارد، نه می‌تواند CSP/منابع شبکه را دور بزند؛ بنابراین راه استاندارد، همین پل «هستهٔ محلی» است.

## راهنمای گام‌به‌گام اتصال به هستهٔ محلی (ویندوز)
1. **نصب هسته**: یکی از این‌ها را نصب و اجرا کنید: [v2rayN](https://github.com/2dust/v2rayN)، [Nekoray](https://github.com/MatsuriDayo/nekoray)، [sing-box](https://github.com/SagerNet/sing-box)، یا Xray خام.
2. **import ساب**: همان لینک سابسکریپشن یا محتوای Base64 را در هسته import کنید (در v2rayN: `Ctrl+V` روی تب اصلی، یا Add subscription).
3. **روشن کردن inbound HTTP**: در v2rayN به Settings → Parameters → Core:基础设置 بروید و مطمئن شوید `LocalHttpPort = 10809` فعال است (SOCKS روی 10808).
4. **وارد کردن در افزونه**: تنظیمات نصیر VPN → بخش «اتصال به هستهٔ محلی» → میزبان `127.0.0.1`، پورت `10809`، طرح `HTTP` → «اتصال به هستهٔ محلی». پس از موفقیت، وضعیت «متصل» نمایش داده می‌شود و تمام ترافیک Chrome از هستهٔ محلی عبور می‌کند.

### پیش‌فرض‌های رایج
| کلاینت | HTTP | SOCKS5 |
|---|---|---|
| v2rayN | 10809 | 10808 |
| Xray (پیش‌فرض config.json) | 10809 | 10808 |
| Nekoray | متغیر | متغیر (در تنظیمات برنامه) |
| sing-box | متغیر | متغیر (در config.json) |

> نکتهٔ امنیتی: `localCore` فقط برای `127.0.0.1`/localhost/IP خصوصی اعتبارسنجی می‌شود — هیچ آدرس عمومی خارجی پذیرفته نمی‌شود و هیچ اعتبارنامه‌ای برای هستهٔ محلی ذخیره نمی‌شود.

## رفتار سرور Nova Proxy (User-Agent)
برخی سرورها (از جمله Nova Proxy) **فرمت پاسخ را بر اساس User-Agent تعیین می‌کنند**:
- UA مرورگر (Chrome) → صفحهٔ HTML رابط کاربری
- UA کلاینت (مثل `v2rayNG/1.8.0` یا curl) → محتوای Base64 سابسکریپشن

افزونه به این ترتیب مقابله می‌کند:
1. تلاش برای ارسال هدر `User-Agent: v2rayNG/1.8.0` در fetch (در MV3 این هدر ممکن است توسط Chrome مسدود شود)
2. در صورت مسدودی، **fallback به declarativeNetRequest**: rule موقت که User-Agent را فقط برای دامنهٔ سابسکریپشن بازنویسی می‌کند و پس از دریافت حذف می‌شود (مجوز `declarativeNetRequestWithHostAccess`)
3. در صورت بازگشت HTML از هر دو مسیر، خطای شفاف نمایش داده می‌شود و **mirror** یا **ورود دستی** پیشنهاد می‌شود

> راه‌حل قطعی: در تنظیمات، لینک mirror از `raw.githubusercontent.com` (نسخهٔ خام Base64) وارد کنید، یا محتوای ساب را در بخش «ورود دستی» بچسبانید.

## محدودیت‌های فنی (مهم)
- پروتکل‌های VLESS/VMess/Trojan/Shadowsocks **مستقیماً توسط chrome.proxy پشتیبانی نمی‌شوند**؛ از بخش «اتصال به هستهٔ محلی» استفاده کنید.
- «تأخیر» نمایش‌داده‌شده زمان پاسخ HTTP است و تضمینی برای سرعت/امنیت/ناشناس‌سازی نیست.
- احراز هویت پروکسی (user/pass) در این نسخه پشتیبانی نمی‌شود.
- هدر `Subscription-Userinfo` (مصرف/حجم) در نسخهٔ فعلی نمایش داده نمی‌شود.

## ساختار
| فایل | نقش |
|---|---|
| `manifest.json` | پیکربندی MV3 (proxy, storage, alarms, declarativeNetRequestWithHostAccess) |
| `src/parsers.js` | parserهای سابسکریپشن (Base64/URI/Clash/sing-box) |
| `src/background.js` | سرویس‌ورکر: دریافت با UA/DNR/mirror، اعمال پروکسی، هستهٔ محلی، تست تأخیر، ورود دستی |
| `popup/` | رابط پاپ‌آپ (نوار هستهٔ محلی، نمایش/انتخاب سرور) |
| `options/` | تنظیمات (لینک اصلی، mirror، فرمت، refresh، timeout، هستهٔ محلی، ورود دستی) |

## راهنمای نصب (Unpacked Extension)
1. مخزن را Clone یا به‌صورت ZIP دانلود و از حالت فشرده خارج کنید.
2. Chrome → `chrome://extensions` را باز کنید.
3. گوشهٔ بالا، **Developer mode** را روشن کنید.
4. **Load unpacked** → پوشهٔ پروژه را انتخاب کنید.
5. آیکون افزونه را باز کنید → «تنظیمات» → لینک سابسکریپشن (و در صورت نیاز mirror) را وارد و ذخیره کنید.
6. در پاپ‌آپ روی «به‌روزرسانی» بزنید؛ سرورها لیست می‌شوند.
7. برای سرورهای HTTP/HTTPS/SOCKS: روی سرور کلیک کنید تا پروکسی اعمال شود.
8. برای سرورهای VLESS/VMess/Trojan/SS: ابتدا هستهٔ محلی را طبق راهنمای بالا اجرا و در تنظیمات وصل کنید.

> نکته: فیلد `icons` در manifest حذف شده است تا Load unpacked بدون خطا کار کند. پس از افزودن فایل PNG آیکون، فیلد را دوباره اضافه کنید.

## امنیت و حریم خصوصی
- بدون `eval` و بدون remote code؛ فقط ماژول‌های محلی.
- **لینک‌های سابسکریپشن (شامل توکن) همیشه ماسک‌شده نمایش داده می‌شوند** (پروتکل و دامنه نمایان، مسیر/پارامترها به‌صورت `****`)؛ نمایش کامل فقط با دکمهٔ «نمایش لینک».
- «حذف لینک»، «حذف mirror» و «پاک‌سازی کامل داده‌ها» کلیدهای مربوطه را فوراً و امن از `chrome.storage.local` پاک می‌کنند.
- توکن/اعتبارنامه‌ها در لاگ یا رابط افشا نمی‌شوند؛ محتوای ساب پس از ورود دستی موفق از textarea پاک می‌شود.
- تنظیمات هستهٔ محلی فقط host/port/scheme را ذخیره می‌کند (بدون اعتبارنامه) و فقط loopback/IP خصوصی می‌پذیرد.
- CSP پیش‌فرض MV3 (بدون inline script).
- rule DNR فقط برای دامنهٔ سابسکریپشن و فقط حین دریافت فعال است و بلافاصله حذف می‌شود.

## مجوزها
| مجوز | دلیل |
|---|---|
| `proxy` | اعمال/حذف پیکربندی پروکسی (شامل پروکسی به هستهٔ محلی) |
| `storage` | ذخیرهٔ تنظیمات و لیست سرورها |
| `alarms` | به‌روزرسانی خودکار زمان‌بندی‌شده |
| `declarativeNetRequestWithHostAccess` | بازنویسی موقت User-Agent فقط روی دامنهٔ سابسکریپشن (fallback برای سرورهایی که بر اساس UA فرمت می‌دهند)؛ rule پس از هر دریافت حذف می‌شود |
| `host_permissions: <all_urls>` | لازم برای (۱) دریافت سابسکریپشن از هر دامنهٔ ارائه‌دهنده و mirror، (۲) تست تأخیر و پروب اتصال به host:port سرورها و هستهٔ محلی. چون دامنه‌ها از سابسکریپشن کاربر به‌صورت پویا می‌آیند، فهرست ثابت دامنه ممکن نیست. این مجوز فقط برای fetch خواندنی/تست استفاده می‌شود و هیچ داده‌ای به سرور سوم ارسال نمی‌شود. تنظیم `localCore` فقط برای 127.0.0.1/IP خصوصی معتبر است. |
